# 出院随访与患者协作 Agent · 设计方案

> 版本：v1.0 ｜ 日期：2026-11-04 ｜ 适用范围：清禾综合医院 · 骨科 2 个病区 · 常规术后患者
> 对应阶段：FDE 04 方案设计 / 05 构建集成 / 06 测试评估 / 07 客户试点
> 读者：护理部、信息科、隐私与质控、专科、患者服务
> 声明：文中除案例设定值（出院人数、完成率、单次时长）外，测算数字与运行记录均为**演练示例**。

## 1. 项目概述

### 1.1 要解决的问题

| 现状 | 量化表现 | 后果 |
|---|---|---|
| 出院名单靠 HIS 手工导出、护士按科室与术式手工分组 | 每月约 1,200 名出院患者全部走人工 | 排程依赖个人经验，晚间时段无法保障 |
| 7 天随访完成率 | 61%，目标 85% | 每月约 290 人未被成功随访（示例测算） |
| 单次随访 | 12 分钟，其中约 4 分钟为重复录入 | 每月约 80 小时重复工时（示例测算） |
| 危险信号识别 | 靠通话中人工听辨，无系统识别与留痕 | 红旗漏报不可逆，质控无法追溯 |

### 1.2 目标与边界

- 试点目标：7 天随访完成率 61% → 85%；单次随访工时下降；红旗升级 100% 留痕。
- 试点范围：骨科常规术后患者、2 个病区、4 周（医疗-003）。
- 范围边界：只做「安排 + 记录辅助 + 红旗升级」，**不做自主诊疗、不调药、不自动挂号开方、数据不出院**（医疗-009、012、013、018）。

### 1.3 成功标准（安全优先）

安全类为零容忍项：任一红旗案例漏报、任一数据出院、任一例无授权录音，即停止试点回退人工流程（傅景叫停权）。业务类按第 10 节阈值判定。

## 3. 方案选型：确定性骨架 + 受限模型

| 候选 | 收益 | 失败方式 | 结论 |
|---|---|---|---|
| A 纯人工优化 | 触达率小幅提升 | 仍靠人盯，红旗无留痕 | 不采纳 |
| B 纯确定性规则 | 排程、时段、搁置可确定化 | 方言与表述差异导致红旗漏报 | 采纳为骨架 |
| C 纯模型方案 | 消除重复录入、红旗召回高 | 误报/漏报、幻觉，失败不可逆 | 限定采纳 |
| **B+C 组合（选定）** | 完成率与工时目标可达 | 红旗漏报 | **进入试点** |

**为什么需要模型**：红旗表述存在大量口语变体（呼吸困难、喘不上气、胸闷、晕厥等），固定关键词表在方言与改写下召回不足，而红旗漏报不可逆——只有"失败不可逆且价值有依据"的格子才允许引入模型，且必须置于护士确认与院内部署的硬约束下。

**模型的三条使用约束**：① 只做陈述整理与红旗提示；② 输出一律为草稿/提示，写入登记表须护士确认；③ 红旗宁误报不漏报，置信度不足一律按红旗处理。

## 4. 总体架构

```
HIS（只读名单接口，医疗-012）
  │ 每日凌晨全量导出：8 字段 + 名单版本号 + 导出时间戳
  ▼
院内随访服务器（无外部网络出口，医疗-013）
  ├─ 排程引擎        术式模板版本过滤（医疗-008）→ 晚间时段优先（医疗-016）
  │                   → 三次未接自动搁置转人工清单（医疗-004）
  ├─ 触达工作台      外呼辅助 + 短信 + 家属协助标注（医疗-011）
  ├─ 红旗规则引擎    固定词表 + 院内模型提示 → 命中即中断问卷
  │                   → 升级工单（医疗-005、015）
  ├─ 记录草稿服务    患者陈述 → 结构化草稿 → 护士确认 → 随访登记表（医疗-006、017）
  └─ 审计留痕库      操作 / 升级 / 授权三类事件全量留痕（医疗-015）
        ▲ 人工复核节点：护士确认所有对外记录｜专科医生处置升级工单｜专科签发模板｜质控只读审计
```

分层说明：

| 层 | 组件 | 部署与约束 |
|---|---|---|
| 接入层 | HIS 只读名单接口、接口替身 | 只读、每日全量、最小必要 8 字段 |
| 业务层 | 排程引擎、触达工作台、红旗规则引擎、记录草稿服务 | 全部院内单机部署 |
| 合规层 | 审计留痕库、授权校验、脱敏与访问控制 | 复用 `aks129/HealthClawGuardrails` 的 PHI 脱敏、不可篡改审计与 step-up 认证能力 |
| 人工层 | 护士确认台、专科处置台、质控审计视图 | 所有对外记录必须有人签名 |

技术选型结论：不 fork 任何开源项目做主框架（全球无成品，详见 [附录-GitHub对标调研.md](附录-GitHub对标调研.md)），自建主框架 + 合规层复用 + 红旗闭环自研；开发与评估使用 Synthea 合成数据。

## 5. 模块设计

### 5.1 排程引擎（确定性规则）

- 输入：当日名单批次（含版本号）、术式模板注册表、护士班次。
- 规则：只纳入有签发版本模板的术式；晚间时段（18:00–20:00，示例）优先；同一患者同一出院批次只排一次；三次未接自动置"搁置"并进入人工跟进清单。
- 输出：当日排程表（按护士分组）、人工跟进清单。
- 失败处理：模板未签发/过期 → 该术式整体转人工，不降级为通用问卷。
- 人工节点：护士可手工调整当日排程顺序。

### 5.2 触达工作台（工具调用）

- 输入：排程条目、联系人信息（本人/家属 + 授权状态）。
- 能力：外呼辅助（一键拨号、脚本提示、通话计时）、短信提醒、家属协助标注。
- 硬约束：授权状态非"已授权"一律不启动外呼与录音；短信发送**不计入**完成率。
- 失败处理：号码失效 → 标记并回写联系人状态（不写回 HIS）；空号/关机 → 计入三次尝试。

### 5.3 红旗规则引擎（规则 + 模型提示）

- 双通道：固定词表（高精度基础召回）+ 院内模型提示（覆盖口语变体）。
- 命中动作：立即中断问卷 → 生成升级工单 → 按院内既有流程转人工，全程留痕。
- 工单字段：触发时间、触发表述原文、命中通道（词表/模型+置信度）、患者标识、处置人、处置结果。
- 阈值策略：模型置信度低于阈值仍按红旗处理（宁误报不漏报），误报由专科在工单中标注"排除"。
- 明确不做：不输出诊断意见、不给用药建议、不替代院内升级流程（医疗-009、018）。

### 5.4 记录草稿与护士确认工作台（模型）

- 流程：通话/问卷内容 → 结构化草稿（主诉、症状、依从性、复诊意向）→ 护士逐字段确认/修改 → 写入随访登记表 → 生成专科摘要。
- 留痕：草稿原值、护士修改值、修改人、时间戳全部保留；护士不确认则只存草稿，不归档。
- AI 不签名：登记表签署人恒为护士（医疗-017）。

### 5.5 审计留痕库（确定性）

- 三类事件：操作（查看/修改/导出）、升级（红旗工单全生命周期）、授权（授予/撤回/录音告知）。
- 字段：事件类型、时间戳、操作者、名单版本、住院号+出院时间、触发原文、处置人与结果。
- 只写不改：质控只读全量，运维不可删改。

## 6. 数据契约

### 6.1 最小必要字段（v1.0）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| 住院号 | string | 是 | 与出院时间联合唯一（医疗-010） |
| 出院时间 | datetime | 是 | 访谈批次锚点 |
| 科室 | string | 是 | 排程分组 |
| 术式代码 | string | 是 | 决定问卷模板版本（医疗-008） |
| 随访状态 | enum | 是 | 待随访/进行中/完成/搁置/已升级 |
| 联系人电话 | string | 是 | 患者本人或家属 |
| 联系人类型 | enum | 是 | 本人/家属；家属须标注（医疗-011） |
| 授权状态 | enum | 是 | 已授权/未授权/撤回；非"已授权"不外呼、不录音（医疗-013、014） |

### 6.2 清洗与版本

- 去重：住院号 + 出院时间。
- 过滤：授权状态非"已授权"的条目不入排程。
- 拒收：清单外字段一律丢弃（医疗-013）。
- 版本：每批次携带版本号与导出时间戳；接口中断时启用上一版本并标记"待补"，超 24 小时转人工。

## 8. AI 职责边界

**三做**

1. 把患者口语陈述整理为结构化草稿，减少护士重复录入（约 4 分钟/次）。
2. 在通话/问卷中提示红旗线索，弥补固定词表的召回缺口。
3. 生成专科摘要与待办建议（仅建议，由人决定）。

**三不做**

1. 不诊断、不建议用药、不解释检查结果。
2. 不自动挂号、不开方、不直接联系患者做医疗决策。
3. 不签名、不归档、不覆盖护士的确认结论。

## 10. 异常与降级设计

降级总原则：**停不下来就转人工，转不出去就停止并报警**；任何异常都产生留痕事件。

| 异常 | 触发 | 处置 | 防重复 |
|---|---|---|---|
| 接口超时/中断 | HIS 导出失败 | 启用上一版本名单并标记"待补"，超 24 小时转人工 | 名单版本号幂等 |
| 缺数据 | 术式代码缺失 | 不入排程，转人工清单 | 处理标记落库 |
| 记录冲突 | 同一患者两条记录 | 按住院号+出院时间合并并提示护士 | 合并日志 |
| 越权 | 非"已授权"被纳入外呼 | 拒绝执行并告警 | 请求前置校验 |
| 授权撤回 | 患者撤回 | 24 小时内停服、停录音、标记历史录音 | 撤回事件留痕 |
| 重复请求 | 排程任务重复提交 | 以（住院号、出院时间、日期）幂等键去重 | 唯一约束 |

## 15. 商务摘要

报价口径：60 人天 × 综合人天单价 2,000 元 = **120,000 元**（不含税）；增值税 6% = 7,200 元；**含税总价 127,200 元**。工期 9 周。

| 序号 | 工作包 | 人天 | 金额（元） |
|---|---|---|---|
| 1 | 需求与流程建模 | 5 | 10,000 |
| 2 | 数据契约与 HIS 接口对接 | 8 | 16,000 |
| 3 | 排程引擎与触达工作台 | 10 | 20,000 |
| 4 | 红旗规则引擎与升级工单 | 11 | 22,000 |
| 5 | 记录草稿与护士确认工作台 | 9 | 18,000 |
| 6 | 审计留痕与合规层 | 6 | 12,000 |
